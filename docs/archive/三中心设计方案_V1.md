# 五六零AI小镇 · 三中心设计方案 V1

2026-09-19。用户已确认采用三中心思路并进行设计。本文件和配套 HTML 为设计交付，业务开发按下文批次另行确认。三中心结构替代《小镇管理后台完整规划_V1》的单一后台结构；七区业务范围继续沿用。

后续确认：用户已同意按本方案完善并要求同域名、同应用的不同路径。最新修订要求管理路径不易猜测，因此下表的 `/manage`、`/admin` 仅为原逻辑命名，不再作为实际地址。实际分别由服务端 `TOWN_MANAGE_ENTRY` 和 `TOWN_SYSTEM_ENTRY` 配置，格式为 `gate-` 加32位随机十六进制字符，两个入口不同。当前已迁移既有居民管理页面到运营入口；独立超级管理员中心仍待实施，预留入口保持404。

地址从不通过公共首页或普通居民账户响应发出；当前授权管理员从个人中心进入运营页面。旧地址返回404，不重定向。随机路径仅减少通用扫描，不代替身份验证、限流或逐请求授权。详细维护见《本地用户注册与后台开发说明》“随机管理入口”章节。

## 1. 产品结构

| 中心 | 页面名称 | 目标人群 | 主要问题 | 建议入口 |
| --- | --- | --- | --- | --- |
| 用户中心 | 我的小镇 | 所有注册居民 | 我是谁、有什么资格、可以做什么、有什么进展 | `/account` |
| 管理中心 | 小镇运营管理中心 | 有岗位授权的工作人员 | 今天要处理什么、我负责什么、如何处理 | `/manage` |
| 管理后台 | 系统管理后台 | 超级管理员 | 谁可以管理什么、系统按什么规则运行 | `/admin` |

共用手机号账户与会话；三个中心不分别注册。登录不意味着能访问管理中心，访问系统后台必须由服务端核验超级管理员身份。游客仍可游览公共场景，打开用户中心时引导登录。

用户头像菜单只显示有权进入的中心。普通居民只有“我的小镇”；工作人员多一个“运营管理”；超级管理员可以进入三个中心。切换中心只改变工作页面，不改变身份、不临时提升权限。

## 2. 用户中心设计

### 首页

顶部为昵称、头像和欢迎语，显示居民身份与当前认证；主区域为已开放功能与个人待办，侧栏为身份、兴趣标签与最新消息。首期没有业务记录时展示下一步引导，不伪造课程、进度或任务。

### 菜单与页面

| 菜单 | 内容与操作 | 数据边界 |
| --- | --- | --- |
| 我的概览 | 当前身份、可用功能、待办和消息摘要 | 仅本人 |
| 个人资料 | 昵称、预设头像、个人简介、脱敏手机号 | 本人可编辑普通资料，手机号变更后续独立验证 |
| 身份与标签 | 认证状态、授予来源/时间、兴趣选择、权限摘要 | 兴趣可选；认证和权限只读 |
| 我的学习 | 班级、课程、课堂、学习记录 | 仅已加入或获得访问许可的资源 |
| 我的任务与活动 | 报名、领取、提交、审核结果 | 仅本人记录 |
| 我的项目 | 团队、共创项目、项目内职责 | 本人为成员且获授权的项目 |
| 我的店铺与作品 | 店铺与作品管理、审核状态 | 仅本人或获店铺授权的资源 |
| 我的社区 | 本人发布、互动与社区通知 | 本人数据与可见公共内容 |
| 我的申请 | 认证、入驻等申请及处理时间线 | 本人申请，可补充退回材料 |
| 消息中心 | 未读/已读、消息类型、相关业务入口 | 接收人为当前用户 |
| 账户与安全 | 登录方式、退出、后续设备管理 | 不显示会话密钥 |

### 功能入口状态

- 已开放且有资格：显示“进入”；无业务记录则显示具体空状态。
- 已开放但需认证：显示条件和“了解申请条件”，已提交则显示处理进度。
- 尚未开发：标记“筹备中”，不显示虚假的申请/提交按钮。
- 临时维护：解释状态并保留历史记录可见性，是否允许编辑由接口决定。

兴趣示例：AI办公、AI绘画、AI编程、AI视频、AI教育、AI创业。兴趣不授予业务权限，不作为实名认证证明。初步建议最多选择5项。

## 3. 运营管理中心设计

桌面采用侧栏、顶部工作区与内容区。顶部显示岗位及数据范围，首页按岗位呈现待办；不具备权限的菜单不展示，直接访问相关 URL/API 仍拒绝。

| 菜单组 | 子模块 |
| --- | --- |
| 工作台 | 我的待办、负责模块、最近操作 |
| 用户与组织 | 居民查询、账户处理、组织成员（按范围） |
| 七区运营 | AI服务中心、AI学院、AI创业园、AI商业街、任务广场、AI社区、五六零AI广场 |
| 内容运营 | 欢迎页与公司介绍、公告、NPC话语、帮助内容 |
| 我的工作记录 | 本人操作、本人处理过的审批 |

七区详情页使用“基础内容 / 业务管理 / 操作记录”结构。首批基础内容可用，业务管理说明后续建设内容，不呈现假的可用表格。

通用列表：搜索、状态筛选、更新时间、负责人、分页；操作根据权限显示。内容编辑分为草稿、预览、发布、下架；“编辑”权限和“发布”权限独立。

居民详情分“基础资料 / 业务身份 / 已授权资源 / 申请记录 / 操作记录”。工作人员只能查看职责所需字段；本批手机号保持脱敏。跨组织的账户停用影响全局，因此只授予全镇用户管理员；学校教师只能移除自己班级的成员资格，不能停用整个居民账户。

## 4. 系统管理后台设计

侧栏：系统概览、工作人员、角色与权限、组织与数据范围、身份与认证规则、模块配置、系统设置、全局审计、维护状态。

### 角色配置页面

采用“角色信息 → 模块动作 → 数据范围 → 授权预览”四段式。保存前列出新增和收回的权限、影响人数及数据范围；后端校验最后一位超级管理员不可被撤权或停用。授权和撤权都记日志，撤权后下一次受保护请求立即受限。

普通工作人员的模块授权与超级管理员资格分开维护，不能通过给普通角色勾选全部权限间接成为超级管理员。超级管理员分配入口不出现在运营中心。

### 系统设置边界

站点运营文案归管理中心；短信供应商、鉴权、模块开关等关键配置归系统后台。首批环境状态只读，真实短信仍未接入。密钥放服务端环境配置或后续安全配置机制，页面不回显原值，也不写进操作日志。

备份恢复、生产发布和数据库破坏性操作不在首批提供按钮；后续需定义明确运维流程。关闭业务模块不删除该模块历史数据。

## 5. 身份、岗位和数据范围

| 概念 | 例子 | 谁维护 | 影响 |
| --- | --- | --- | --- |
| 兴趣标签 | AI办公、AI绘画 | 用户从标签库中选择 | 个性化展示，不授予访问权 |
| 业务身份 | 小镇居民、学员、OPC成员 | 系统默认/审批/有权人员 | 表示资格，不直接开放全部资源 |
| 工作岗位 | 内容运营、教学管理、审核员 | 超级管理员授权 | 决定能执行的管理动作 |
| 资源权限 | 某班级、某课程、某项目 | 有权工作人员按规则分配 | 决定具体资源访问范围 |
| 数据范围 | 本人、指定班级、指定组织、指定街区、全镇 | 系统后台配置 | 限制查看与操作对象 |

建议角色模板：内容运营员、教学管理员、服务中心审核员、任务运营员、园区运营员、商业街运营员、社区管理员、用户管理员。一个人可有多个岗位。服务端使用明确的 `模块.动作` 权限，而不是仅比较角色名称。

在同一模块内按明确授权合并范围；缺省无权限。未定义规则的范围不自动扩大到全镇。记录所有者、组织/班级归属要来自数据库，不采信客户端传来的归属值。

## 6. 首批权限示例

| 操作 | 普通居民 | 内容运营员 | 全镇用户管理员 | 超级管理员 |
| --- | --- | --- | --- | --- |
| 修改本人资料和兴趣 | 本人 | 本人 | 本人 | 本人 |
| 查看/停用居民账户 | 无 | 无 | 授权范围 | 可在运营中心操作 |
| 编辑七区介绍和NPC话语 | 无 | 被分配的街区 | 无 | 可在运营中心操作 |
| 发布内容 | 无 | 另需发布权 | 无 | 可在运营中心操作 |
| 分配工作人员与权限 | 无 | 无 | 无 | 有 |
| 修改系统关键配置 | 无 | 无 | 无 | 有，具体功能分批开放 |
| 查看审计 | 本人业务结果 | 本人工作记录 | 授权范围记录 | 全局 |

## 7. 数据与接口设计方向

复用 Better Auth 用户、会话和现有居民资料。新增概念建议为：兴趣标签及用户关联、业务身份及授予记录、工作人员角色/权限/范围、模块配置、带发布版本的内容和审计事件。组织、班级和课程表在对应业务批次建立。

资料、身份、授权只保留唯一数据源，三个中心通过不同权限接口读取。用户入口不能使用管理接口编辑自己不应修改的身份。不得信任浏览器切换中心的状态作为鉴权依据。

建议接口分层：`/api/account/*`（本人）、`/api/manage/*`（岗位+范围）、`/api/admin/*`（超级管理员）。现有 `/api/admin/users` 在迁移中明确替换为运营中心接口，旧地址不得继续绕过新权限校验。

内容使用草稿版本和已发布版本；保存草稿不影响前台。预览只对有权工作人员开放；对外接口仅返回已发布内容。七区保留现有稳定 ID，内容配置不直接编辑建筑布局或3D招牌。

## 8. 现有账户迁移

现有 `user/admin` 角色不足以表达三中心，需要显式迁移。保留所有居民、资料和会话数据。由维护命令指定超级管理员账户，不批量提升现有管理员；原有管理员的运营角色要逐一明确映射。

本机演示管理员 `19900000999` 可作为首位超级管理员的候选，正式实施前在该批清单中明确。当前设计未更改该账户权限。后续授权由系统后台管理，普通注册始终只有居民身份。

## 9. 视觉和交互

三个中心共用数字560品牌、浅色背景、白色卡片及蓝色主按钮。用户中心更重视个人欢迎、身份卡和功能卡；运营中心更重视待办、筛选和列表；系统后台更重视权限、范围和配置说明。

桌面固定侧栏，内容区滚动；手机侧栏变为可开关导航，点击菜单后收起。键盘可操作、焦点可见，状态同时有文字说明。页脚统一公司全称。

配套《三中心界面原型_V1.html》可切换三个中心与菜单，展示布局、资料兴趣选择、运营模块和权限表。原型中的用户/岗位为设计示例，指标不填虚构数值；不连接数据库、不验证权限、不保存资料。原型切换器仅为评审工具，正式产品按登录账户实际资格展示入口。

原型为自包含 HTML，可直接用浏览器打开，无需依赖或网络素材。本次已在桌面和390×844手机尺寸检查中心切换、菜单导航、手机菜单展开及权限表格布局。主项目业务代码未因本次设计发生变更。
