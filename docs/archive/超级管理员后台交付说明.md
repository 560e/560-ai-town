## 入口与账户

使用原先预留的 `TOWN_SYSTEM_ENTRY` 独立随机路径，与小镇和运营中心共用3000端口。入口仅随超级管理员的本人账户响应返回；运营管理员和普通居民不会获得它。知道路径也不等于获得权限，每个系统接口单独校验数据库中的最新角色。

本地测试手机号 `19900000999`（当前昵称“五六零”）已通过明确的维护命令设为首位超级管理员；原有昵称、头像和居民资料保留，其他账户没有自动提升。旧会话在角色变更时被撤销，重新登录即可。

使用方式：打开 `/account`，使用本地测试验证码登录，在“我的账户”中点击“进入系统管理后台”。同一账户仍可进入运营管理中心。

## 已实现页面

| 页面 | 实际功能 |
| --- | --- |
| 系统概览 | 居民、运营管理员、超级管理员真实数量；管理模块入口 |
| 工作人员与授权 | 按手机号/昵称搜索、角色筛选、分页；对已注册用户授予或收回管理角色 |
| 角色与权限 | 展示三个固定角色当前实际可用权限，并链接至人员授权 |
| 全局操作日志 | 分页和操作类型筛选；展示操作者、对象、时间、原因和角色前后变化 |
| 系统状态与设置 | 只读环境、数据库连接、登录方式、短信/双重验证接入状态；不返回密钥或数据库凭据 |

角色变更表单先展示目标用户、原角色、新角色和影响，必须填写原因后确认。降低角色不会删除居民资料，但会撤销目标账户所有现有登录会话。

## 当前权限

- `user`：小镇居民，个人中心和公共场景。
- `admin`：运营管理员，现阶段可管理全镇居民，读取运营统计与本人工作记录。
- `super_admin`：超级管理员，同时具备运营中心访问权和独立系统后台权限。

不允许修改自己的管理角色；角色变更在事务和全局授权锁下执行，重新检查操作者资格，并防止移除最后一位正常超管。运营中心不允许停用任何管理账户，需先由另一位超管收回其管理角色。

注册和个人资料接口无法写入角色；普通运营管理员也不能调用系统授权接口。框架自带管理接口继续不对外开放。

## 首位超管维护命令

```text
npm run admin:grant -- --phone 19900000999 --super-admin
```

此命令用于明确指定的已注册账户，不自动选第一位用户。它不会把其他管理员一并提升，也不会把已是超管的账户意外降为运营管理员。普通运营管理员授权仍可用不带 `--super-admin` 的命令。

生产时不要沿用演示账户和本地验证码模式。当前账户服务仍受已有开发环境和回环地址限制，生产账户接口保持关闭。

## 本期边界

角色目前为上述三个固定角色；岗位自定义、学校/班级/街区资源范围、认证审批规则和模块开关尚未接入。系统设置当前为状态读取，不提供短信密钥编辑、生产部署、备份恢复或双重验证操作。已确认的完整三中心计划仍有后续业务需要实施，不能把本次基础后台交付理解为全部完成。

## 关键实现

- `lib/roles.ts`：统一角色及名称，运营访问资格。
- `lib/server/session.ts`：独立 `requireSuperAdmin`，按当前角色返回入口。
- `lib/server/role-management.ts`：事务授权、撤销会话及角色变更审计。
- `app/api/system/{users,overview,audit}/route.ts`：超管专属接口。
- `components/account/SystemCenter.tsx`、`app/system.css`：系统后台。
- `scripts/admin-account.ts`：首位超管授权与防误降级。

## 验收范围

接口检查涵盖游客401、普通居民/运营管理员403、私有入口按资格返回、真实统计、非法角色与空原因拒绝、跨来源拒绝、自身角色保护、授权/撤权、目标会话失效、角色前后变化审计、管理账户停用保护、撤权后即时拒绝系统接口。

浏览器验证个人中心超管身份、独立入口、系统概览、人员列表与授权表单、全局日志、系统状态，以及手机尺寸布局。集成检查只创建/修改并清理独立的临时测试账户，不修改演示居民的权限。

2026-09-19 验收结果：30 项项目测试、58 项账户集成检查、TypeScript 类型检查和生产构建全部通过。浏览器同时验证了超级管理员可进入运营中心；手机测试使用 390 × 844 视口，完成后已恢复默认视口。
