# 五六零人工智能AI小镇 V0.0.1 项目完整说明

发布整理日期：2026-09-20。所属公司：五六零人工智能科技（北海）有限公司。

本文件是 V0.0.1 的当前功能基线。历史文档中的 V0.12、第一批/第二批等指迭代记录，不是本次对外版本号；与历史说明矛盾时，以本文件及实际源码为准。

## 1. 项目定位

以北海滨海气质为背景的交互式 AI 社区小镇，为愿意学习、探索 AI 的人，以及学校合作伙伴、OPC 客户和共创者提供统一入口。游客可以游览主地图、与NPC互动；注册登录后可以进入七区子页、申请身份、参与多人房间，并通过身份获得已配置资源的访问权限。

当前场景是概念沙盘，不是北海真实地理模型；3D 外观不表示已经具备对应的课程、商业交易或住宅分配业务。

## 2. 已完成的场景与交互

- 关于小镇为默认主页，左侧介绍、右侧实时 3D 沙盘，可拖动预览；点击“游览小镇”进入全景。
- 全景支持 360°旋转、缩放；黄色立体箭头位于七区入口，登录后点击直达子页面；游客会先看到注册／登录提示。
- 步行支持 WASD/方向键、Shift、拖动转向、滚轮缩放和第一/第三人称，移动与障碍碰撞处理；手机提供虚拟摇杆。
- 七区快捷导航均落在对应入口，服务中心在门前；个人中心返回时恢复进入前的场景状态，不强制绕回欢迎页。
- 可坐长凳、靠近 NPC 按 E 对话、按 Enter 发言；NPC 话语与当前区域相符。
- 小镇有蓝天白云、缓慢转动的 560 海浪雕塑、动态车辆、随机行人、默认关闭的轻环境声。
- 全站屏蔽浏览器右键菜单，减少操控误触；左键与滚轮行为保留。

## 4. 用户与三中心

访问规则：游客只可在主地图全景或步行模式浏览，七个版块子页面统一要求注册／登录，包括直接访问链接和服务内容接口。注册提示取消后仍留在主地图；在提示中登录后继续进入选定版块。公开称号、公开资料中的“公开”表示对已登录居民开放，不表示允许匿名访问；受限资料仍继续核验对应称号权限。

### 用户账户与居民工作台

手机号注册/验证码登录；首次成功验证创建普通居民账号。昵称与账户绑定且不能重复，可设置头像、衣服、发型和发色。当前验证码是受回环访问限制的本地测试码，没有真实短信发送。

居民工作台按个人概览、我的学习、我的企业与共创、我的作品与店铺、我的任务与活动、我的社区、我的服务、我的身份、账户与形象组织。概览使用真实身份、申请、待办、通知数据；未来业务明确标为筹备，未填造示例班级或企业。

可选最多10个有效身份用于公开展示并排序；昵称下方首先显示6个，每排3个、最多2排，其余通过“+数量”展开。身份支持运营定义的色彩、渐变、边框；失效或撤销身份不能继续展示，远处角色隐藏身份以控制拥挤。

### 运营管理中心

独立随机路径；工作人员依实际授权管理居民、服务称号、分类、资料、申请审核、授予/撤销、敏感词和运营记录。支持申请软删除和所选记录批量处理；具备相应岗位权限的工作人员可审核自己的申请。身份称号不会自动提升为管理角色。

### 系统管理后台

独立随机路径，仅超级管理员进入。管理固定账号角色、工作人员服务范围、系统审计、站点设置。可设置首页 Logo/标题、站点图标和分享信息、公司/版权/ICP备案/公安备案，支持预览、配置版本与恢复。

私有路径不是唯一安全措施：后端仍检查登录状态、角色、岗位范围及操作权限。`/admin` 和 `/manage` 不作为公开管理入口。

## 5. 服务中心身份机制

- 业务属性分“荣誉称号”和“权限称号”；可独立设置学习类、共创类等分类。
- 后台分别控制发布/隐藏、允许申请/人工授予、申请表字段、有效期、展示样式和头顶展示开关。
- 用户提交申请后，可经历草稿、待审核、退回补充、通过、拒绝、撤回等状态，并收到对应通知。
- 权限称号可绑定已经实现的资源访问权限；当前可绑定的实际业务是服务资料阅读。未来课程、项目等要待对应业务完成后再接入。
- 荣誉称号只表达荣誉，不直接授权业务功能。企业成员身份也不等同于装饰性称号。

## 6. 多人、房间与聊天

- 主地图真实多人在线同步昵称、形象、位置、朝向、动作和身份；通过同源 API 与 PostgreSQL 共享状态，不需要另外开 WebSocket 端口。
- 房间号范围1–999999，默认最多50账号；绘制预算与容量不同，场景最多渲染30个人物（含NPC），不会把50个账号全部无差别堆在画面上。
- 1号房间保留；其他房间在最后用户离开、或最后在线租约失效后释放。房间可设密码，列表显示锁标记。
- 创建者为房主，可踢人。被踢者寻找可加入的公共房间，满员时顺延；踢出不等于永久封禁。
- 同房间可互见公开气泡；靠近另一用户可按E发起私聊，等待对方同意后才显示双方聊天框。
- 敏感词在服务端参与公开/私聊消息检查，运营可增加、修改、禁用、删除和导入规则。
- 现有聊天不是完整历史归档产品。服务中心大厅仍为个人互动场景，尚无大厅多人同步；NPC/车辆不是权威同步交通模拟。

## 7. 技术结构

| 层 | 当前技术 |
| --- | --- |
| Web应用 | Next.js 16.3.5 App Router、React 19.2、TypeScript |
| 3D | Three.js、React Three Fiber、Drei |
| 登录基础 | Better Auth 1.7.5 + 当前本地手机号测试流程 |
| 数据 | PostgreSQL、pg连接池、迁移脚本、数据库审核记录 |
| 资源 | 本地几何体、本地挤出文字、本地天空/音效；不依赖远程模型 |
| 部署 | Node.js 24、单应用多路径、systemd；游客模式可加Nginx |

`app/` 为页面和API；`components/town/` 为主地图；`components/service/hall/` 为大厅；`components/account/` 为三中心；`lib/server/` 为认证、权限、申请、房间等服务；`data/` 为场景布局与交互；`scripts/` 为环境、建表、部署与打包；`tests/` 为回归和集成检查。

外观与稳定版块 ID 分离，为以后更换主题提供基础，但当前没有换肤产品功能。移动端已有布局适配；真实手机 GPU 的性能仍需设备测试。

## 8. 数据与交付范围

V0.0.1 是源码发布包，在 Debian 上安装锁定依赖并构建。不会把 Windows 的 `.next` 或 `node_modules` 复制到 Linux。

包含源码、静态资源、迁移、测试、历史设计记录、新版说明、安装脚本、维护脚本、文件清单与校验值。

不包含开发机 `.env.local`、真实密钥、用户手机号列表、数据库文件、已上传 Logo、会话、日志、截图或临时QA数据。新服务器为全新数据：默认站点配置、服务内容和初始敏感词由迁移建立；个人用户、已发布称号与运营数据不随源码迁移，需在服务器重新配置。

如需搬迁现有数据，应另行安排数据库和 `.local/site-assets` 配套备份/恢复。不要把本地目录整体覆盖到服务器。

## 9. 测试与正式上线界限

V0.0.1 可部署到 Debian 测试，但不是“短信已接入的公网正式运营版”。本轮保持现有认证限制，没有把测试验证码暴露到公网。部署选择与操作详见《V0.0.1 Debian部署说明》。

正式公开注册前，还需单独完成短信供应商接入、生产认证策略、HTTPS与域名配置、真实设备/并发验证及运营内容准备。课程、企业、店铺和住宅业务继续按批次规划并确认后开发。
