# 五六零AI小镇 · 系统设置完整规划 V1

日期：2026-09-19。状态：规划稿，供用户确认实施范围。本次仅整理设计，不代表下列功能已经实现，也不授权一次性开发全部模块。

## 1. 当前基础与目标

当前已实现：手机号本地测试登录、居民资料、运营居民管理、超级管理员人员授权、三个固定角色、全局操作日志，以及只读系统状态。短信、双重验证、细粒度岗位权限和七个版块的业务尚未接入。

本规划在现有同域名、不同路径的三中心结构上扩展，不另开管理端口。超级管理员后台负责全站规则和系统配置；运营中心负责日常内容与业务；个人中心负责本人资料和记录。

用户最新提出的需求：运营中心“七区运营”统一改为“版块管理”；超管可设置首页左上角 Logo 和文字，以及底部公司、ICP备案和公安联网备案信息。

## 2. 后台导航结构

建议保留系统概览、工作人员与授权、角色与权限、全局操作日志；随业务推进增加组织与数据范围、身份与认证规则、版块配置。

现有“系统状态与设置”拆成：

- 系统设置：按主题编辑全站配置。
- 运行与维护：查看运行状态、服务异常及备份状态，维护操作按后续批次开放。

尚未实现的设置不提供可保存的假表单，也不能通过开关把尚未开发的业务变为“已开放”。

## 4. 站点与品牌

### 首页标识

- 支持上传、更换、移除 Logo，并编辑右侧品牌文字。
- 没有上传图片时使用现有数字“560”；品牌文字默认“五六零人工智能科技”。
- 首批图片支持 PNG、JPEG、WebP，建议使用透明背景 PNG/WebP；限制文件大小、实际格式和像素尺寸。首批不接收 SVG 或任意 HTML。
- 保持图片比例，限制显示高度和文字长度，提供桌面与手机预览，避免挤压顶部布局。
- 设置的是网页品牌，不自动更改3D门头、建筑招牌、560雕塑或稳定版块ID。

### 页面与分享信息

- 浏览器标签标题、站点描述、浏览器图标、分享标题/描述/封面。
- 可配置公开站点地址供分享使用；认证回调、可信来源和服务端实际域名仍通过部署配置管理，不能随意跟随表单值更改。
- 分享封面未设置时使用默认封面。搜索与社交平台可能有缓存，保存成功不承诺其立即更新。

## 5. 公司与底部信息

| 字段 | 默认或行为 |
| --- | --- |
| 公司全称 | 五六零人工智能科技（北海）有限公司 |
| 版权说明 | 可编辑纯文字，可选显示当前年份 |
| ICP备案号 | 独立字段，未填写则不显示 |
| ICP查询链接 | 与号码配对设置，仅允许有效 HTTPS 链接 |
| 公安联网备案号 | 独立字段，未填写则不显示 |
| 公安备案查询链接 | 与号码配对设置，仅允许有效 HTTPS 链接 |
| 服务联系方式 | 后续可增加公开客服邮箱、电话、服务时间、二维码；每项明确展示位置 |

备案信息由公司提供真实内容，不填演示号码，不显示“已认证”等推断。输入号码但缺少查询链接时给出明确提示，保存规则在表单中说明。

首页欢迎页、进入小镇后的页脚使用同一份公司与备案配置。个人中心及管理中心可复用同一组件，保持一致，分别适配布局。桌面居中、手机换行，不遮住行走导航、对话和底部按钮。业务联系信息不默认全部塞进页脚，可放“联系我们”。

## 6. 访问、账户和身份规则

- 游客默认可以浏览公共小镇，保持现有产品方向。
- 账户默认身份固定为“小镇居民”，普通注册不能通过设置获得管理角色。
- 未来关闭新注册时，已注册用户仍可登录；业务接口必须执行规则，不能只隐藏按钮。
- 学员、OPC共创成员、学校合作成员属于业务资格；课程、班级、项目的具体访问权另行授权。
- 用户自选兴趣标签不授予认证或业务权限。
- 用户协议与隐私政策提供版本、发布时间及前台入口；具体文本由公司确认。后续登录注册流程记录用户确认的版本。
- 真实短信接入前保留本机开发验证码模式，不增加可在生产环境开启测试验证码的后台开关。
- 管理员二次验证、会话管理、异常登录限制作为生产接入批次。限制值使用受控范围，不能设置为无限制或通过空值关闭保护。
- 随机管理路径不作为唯一保护。暂时保留部署端维护，后续若做后台轮换，要设计重新验证、变更记录和可靠恢复流程。

## 7. 版块、运营与权限的分工

| 设置或业务 | 负责位置 |
| --- | --- |
| 品牌Logo、公司主体、备案、全站登录与安全规则 | 超级管理员后台 |
| 欢迎介绍、版块介绍、公告、帮助、NPC随机话语 | 运营管理中心，按岗位授权 |
| 课程、班级、课堂、任务、活动、店铺、项目和社区内容 | 运营管理中心对应版块 |
| 学员/OPC认证类型与审批规则 | 超管定义规则；运营中心处理具体申请 |
| 工作人员岗位、管理范围、学校组织隔离规则 | 超级管理员后台 |
| 本人昵称、头像、兴趣、学习及申请记录 | 用户中心 |

统一将运营界面的“七区运营”改名为“版块管理”，保留七个现有版块和稳定ID。

版块状态需区分“筹备中”“开放”“维护中”；入口可见性与访问资格分开。关闭入口不删除历史数据，维护时能否查看历史记录、能否提交或编辑需逐接口明确。未实现的业务不能被超管开关强行开放。

权限应逐步细化为岗位、动作、数据范围；教师管理指定班级，学校管理员管理指定学校，不能因此停用全镇账户。当前仍是三个固定角色，细分规则尚未实现。

## 8. 上传、第三方服务与运行维护

- Logo首批先支持本地持久化文件；文件使用服务端生成的名称，校验真实图片内容，替换后保留旧版本用于恢复，不立即删除仍被引用的资源。
- 以后接阿里云OSS或其他对象存储时保持资源标识稳定，业务不依赖特定服务器目录。
- 密钥、数据库口令不出现在公开配置、预览、操作日志中。首期服务端环境配置管理秘密，后台只显示已配置/未配置；未来如支持录入，采用替换式而非回显原值。
- 短信设置规划供应商、签名、模板和发送状态；测试发送需明确接收号码，并遵循发送限制。
- 运行页区分健康检查时间与实时状态，展示故障摘要，不把完整异常堆栈或连接凭据发到浏览器。
- 备份包含数据库、上传文件和必要部署配置；先建立备份与验证恢复流程，再考虑后台操作入口。恢复操作需要额外核验、影响说明及操作记录，不做普通保存按钮。
- 全站维护模式需要明确管理后台和恢复入口的可用性，避免关闭站点后无法恢复。
- 暂不加入支付、财务、积分商城、自动部署、任意脚本、任意数据库编辑等未提出的功能。

## 9. 所有设置共用的交互与数据规则

1. 按分类独立保存，标明影响范围和生效方式；存在未保存修改时，离开页面提示。
2. 公开外观配置使用“编辑→预览→保存并生效”；保存前不改变用户正在看到的内容。
3. 显示最后修改时间与修改人，记录配置版本、修改前后内容；秘密字段只记录更换事件。
4. 支持按配置组恢复上一版；恢复也生成新版本和审计记录，不抹除历史。
5. 使用版本号避免两位管理员互相覆盖；发现其他人已更新时，提示重新读取再编辑。
6. 所有写接口由服务端核验超级管理员资格、字段格式和请求来源。普通运营用户即使知道接口地址也不能更改。
7. 对外仅返回明确允许公开的品牌/公司/备案等字段，独立于安全配置、人员授权和管理入口信息。
8. 保存失败保留输入并说明原因；读取失败保留默认展示或最近发布的有效配置，不让欢迎页因设置服务故障变成空白。
9. 站点设置数据独立于场景底模和建筑外观；不接受直接编辑程序配置或注入HTML/脚本。

## 10. 建议分批开发

### 第一批：站点品牌与底部信息

- “七区运营”改为“版块管理”。
- 系统设置/运行状态分离。
- 首页Logo上传与品牌文字、浏览器图标、页面标题及描述、分享封面。
- 公司、版权、ICP备案和公安联网备案信息。
- 桌面/手机预览、数据库持久保存、公开展示、权限校验、版本检查、修改日志和上一版恢复。
- 未设置项保持现有默认外观；不改3D建筑招牌。

这一批即可让公司品牌和基础公开信息不用改代码就能维护。相较上一轮提出的最小清单，本规划增加了图标、页面/分享信息和版本恢复，需一并确认后才纳入实施。

### 第二批：账户与正式部署准备

注册规则、协议与隐私入口、真实短信、管理员二次验证、会话管理、上传存储、服务状态及备份恢复流程。仍先在本地完成验证，实际生产接入另行明确。

### 第三批：业务和组织规则

优先随服务中心实现认证规则、申请及审批；再随学院实现学校/班级授权。其他版块按实际业务逐一加入开放条件、岗位、通知规则。避免先做没有业务承接的配置表。

### 第四批：小镇体验与维护优化

在需要时增加声音资源、画质偏好、场景参数、运行告警和维护工具。NPC台词属于运营内容，NPC行为算法和建筑布局修改仍单独评审。

## 11. 首批验收标准

- 超管保存后刷新仍保留配置，游客和居民可读取已发布的公开信息。
- 普通居民和运营管理员不能修改配置、上传Logo或读取秘密配置。
- 无Logo/无备案内容时显示正确默认状态；长文字和手机页脚不溢出。
- 图片不拉伸；错误文件、超限文件和不允许的链接被拒绝。
- 预览不影响正式展示；版本冲突不覆盖他人修改；恢复留下日志。
- 页脚不遮挡导航、NPC对话和座椅提示，小镇原有鼠标、键盘、行走功能保持正常。
- 通过类型检查、相应权限和持久化集成验证、现有布局/路径测试及生产构建，并检查桌面和手机视图。
