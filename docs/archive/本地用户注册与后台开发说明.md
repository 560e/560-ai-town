## 首次安装和日常启动

需要 Node.js 24、npm 和 PostgreSQL 二进制程序。当前 Windows 已使用 PostgreSQL 17 实测。脚本可探测 Windows 默认 17 安装路径及 Linux `/usr/lib/postgresql/15..18/bin`；其他位置通过 `PG_BIN` 指定。

在项目根目录运行：

```text
npm ci
npm run local:setup
npm run local:dev
```

PowerShell 若限制 npm.ps1，可改用 `npm.cmd`。

`local:setup` 启动独立本地数据库、生成环境配置并执行表结构迁移；已有数据库可重复执行。后续启动使用 `npm run local:dev`，或现有一键脚本的开发模式：

```powershell
.\start-windows.bat --dev
```

```bash
bash start-linux.sh --dev
```

指定不同网页端口可用 `--port 3001`；一键脚本会同步当前开发进程的账户来源地址。直接使用 `npm run dev -- --port 3001` 时，需要自己同步 `.env.local` 的 `BETTER_AUTH_URL`。

Debian 需先安装 Node.js 24 和 PostgreSQL，例如由管理员安装 `postgresql` 后，在**普通用户身份**下执行项目命令。`initdb` 不允许使用 root。脚本不会更改系统已有 PostgreSQL 服务，而是在项目目录创建另一个集群。Debian 完整安装尚待实机验证。

### 数据位置

| 位置 | 内容 |
| --- | --- |
| `.local/postgres/` | 项目数据库集群，端口 55460，仅监听 127.0.0.1 |
| `.local/database.json` | 随机生成的本地数据库凭据 |
| `.local/postgres.log`、`.local/setup.log` | 数据库运行与初始化日志 |
| `.env.local` | 数据库连接、会话密钥、本地模式和站点地址 |

上述私有文件已加入忽略规则；不要提交、对外发送或当缓存删除。应用数据库角色为 `town_app`，不具有超级用户、创建角色和创建数据库权限。数据库名为 `town_local`。

如果根目录已存在 `.env.local` 而没有项目数据库配置，初始化脚本不会覆盖它，需要自行启动 `DATABASE_URL` 指向的数据库，再运行 `npm run db:migrate`。配置字段参见 `.env.example`。

停止网页进程用 Ctrl+C；停止项目数据库用 `npm run db:stop`。网页进程关闭并不自动停止数据库。迁移或搬机前做数据库备份；不要把运行中的数据库目录直接复制为备份，也不要将 Windows 数据目录直接拿到 Linux 使用。跨系统应使用 PostgreSQL 逻辑导出/恢复，生产部署另行规划。

### 管理员授权

已注册并验证的本地账户可以通过项目维护命令授予管理员权限：

```text
npm run admin:grant -- --phone 19900000999
```

需要创建专用本地演示管理员时：

```text
npm run admin:grant -- --phone 19900000999 --create-local
```

`--create-local` 只允许本地模式。此命令是维护工具，不是居民可调用的接口；前端不能修改角色。恢复其他机器上的项目不会自动创建这两个演示账户，需要自行注册或执行上述命令。

## 技术结构与接口

### 随机管理入口（后续修订）

仍使用同一应用和端口3000，未来部署时也共用560e.com，不需要为两个管理中心开放额外端口。

- `.env.local` 的 `TOWN_MANAGE_ENTRY` 保存运营入口路径段，`TOWN_SYSTEM_ENTRY` 保存独立系统入口路径段；格式为 `gate-` 加32位随机十六进制字符。
- `npm run local:setup` 会为项目自行管理的本地配置补齐缺失的地址；已有配置也可执行 `node scripts/management-entry.mjs`。只补缺失项，不覆盖已有值，每次启动不会重新生成。不要使用 `NEXT_PUBLIC_` 变量或将地址写入公共页面。
- 当前运营入口承载已有居民管理；独立系统入口仅预留，仍返回404，不意味着超级管理员权限体系已完成。当前管理员角色没有自动升级。
- 只有通过当前服务端管理员身份检查的账户响应才包含运营入口；普通用户不获得它。新页面设置 noindex/nofollow 和 no-referrer，旧 `/admin`、`/manage` 返回404且不重定向。重命名地址后须重启运行服务并更新工作人员书签。
- 两个路径必须不同；缺失、重复或不符合格式时管理页面关闭。请使用系统密码学随机源生成新路径，不使用生日、公司名或短数字。
- `/api/admin/users` 等现有接口仍保留明确路径并继续严格鉴权，页面随机化不是接口防护。短信校验接口仍限流。上线前再单独确认超级管理员双重验证等措施，当前未新增该功能。
- 当前修订验证：30项单元/场景/启动测试、33项账户集成检查、类型检查和生产构建通过，覆盖旧路径404、居民不接收入口、管理员新入口可访问、系统预留入口关闭。

沿用 Next.js，采用 Better Auth 1.7.5 处理手机号账户与 Cookie 会话，PostgreSQL 保存状态；未引入另一套大型后台系统。

| 文件/目录 | 职责 |
| --- | --- |
| `lib/account.ts` | 手机号规范化、脱敏、资料校验及头像配置 |
| `lib/server/auth.ts` | Better Auth、手机号插件、会话与事件记录 |
| `lib/server/config.ts`、`http.ts` | 本地环境、来源限制、输入大小及错误响应 |
| `lib/server/otp.ts` | 验证码哈希、过期、尝试次数、并发消费与限流 |
| `lib/server/session.ts`、`db.ts` | 数据库、最新角色/停用状态检查与事务 |
| `app/api/auth/[...all]/route.ts` | 仅开放获取验证码、验证和退出 |
| `app/api/account/route.ts` | 当前会话、居民资料更新 |
| `app/api/admin/users/` | 后台列表、详情、停用/恢复及审计读取 |

## 本地验证码与权限规则

- 验证码为随机六位数字，有效期 5 分钟；同一手机号 60 秒后可重新获取，每小时最多 10 次。
- 单条验证码最多错误尝试 5 次，同一手机号 10 分钟最多验证 20 次。框架另有限制请求来源的速率规则。
- 数据库只保存验证码 HMAC；框架生成时的临时明文记录会删除。验证码在事务中只能成功消费一次，并发提交不能重复使用。
- 会话存于服务端，使用 HttpOnly Cookie，期限 7 天并按框架规则续期；退出会撤销服务端会话。
- 写操作验证来源、JSON 格式与字段白名单；不能通过资料接口或注册参数提升权限。请求体限制 4 KB。
- 管理接口每次查询真实角色及停用状态，前端隐藏按钮不是权限依据。
- 本地测试必须为开发模式、回环地址和 `TOWN_LOCAL_AUTH=1`；一键启动器拒绝将本地账户模式与 `--lan` 合用。不要给开发服务做公网隧道或反向代理。
- `next build` / `next start` 的生产模式强制关闭账户功能，即使保留本地标记也不会返回验证码；游客场景仍可访问。
