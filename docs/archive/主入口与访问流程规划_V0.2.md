状态：游客浏览、真实登录后置与场地先行已获用户确认；场地批次已实施，正式校门与访问流程仍为后续待确认提案。

## 已确认的阶段决策

- 允许游客浏览小镇。
- 当前优先完成小镇场景设计与视觉验证，先形成可查看的雏形。
- 真实登录后续再接入，当前不开发账号系统、认证服务或登录表单。
- 当前入口以“游客进入”为有效操作，登录最多以非交互文字说明“后续开放”。
- 首次视觉验证包括主校门、整体空间布局、六个核心场所和基础环境；先判断整体效果，再逐批细化。
- 以上决策不替代逐批开发确认约定。下方未确定的方案仍属于提案。

用户新增需求：增加类似大学校门的主体入口，名称为“五六零人工智能AI小镇”，作为用户首先访问和登录的入口。

本文件补充《项目方案草案 V0.1》，并替代其中“打开后直接展示小镇全景”“不设置登录入口”以及南侧布局的相应提案。其他未涉及内容继续作为待确认方案。用户最新需求优先于原始文档；实际登录纳入本次规划，但实施时机和方式尚待确认。

## 1. 入口的作用

主入口同时承担品牌展示、首次到访接待、账号登录和进入小镇四项作用。空间结构调整为“一个主入口＋六个核心场所”。主入口是独立场景组件，位于同一个小镇空间内。

首次访问先看到校门近景，门后可看到主路和部分小镇建筑，让用户明确自己即将进入什么地方。建议使用同一个 3D 场景切换入口视角与全景视角，入口上叠加简洁的网页操作面板。

首屏内容以校门和进入操作为主，不增加长篇营销介绍。

## 2. 校门外观

- 形态：两侧白色立柱连接横向门楣，主体宽而通透，保留宽阔中央通道和低矮两翼。
- 门楣主名称：严格使用“五六零人工智能AI小镇”，不替换为缩写或旧项目名。
- 配色：白色结构、深蓝文字、少量科技蓝和青色灯带，与小镇整体一致。
- 标识：可在一侧设置简洁的 560 几何标识，不增加未经确认的徽章或吉祥物。
- 门前：小型迎宾广场、两侧绿化及少量棕榈树，保持通行轴线开阔。
- 门后：一条短而清晰的主路直达中心广场，中心地标与校门形成呼应。
- 比例：门楣足够宽，容纳完整名称；高度低于主要楼宇，不遮住全景中的教学楼和中心地标。
- 手机显示：入口界面同步显示完整名称，不依靠缩小后的 3D 门楣文字承担全部识别任务。

具体尺寸和文字字号在开发获准后以桌面、手机画面验证。

## 3. 布局调整

```text
                           北
                       OPC 教学楼
          政务大厅           │
                  ╲         │
    OPC 写字楼 ────── 小镇中心广场 ────── OPC 商业街
                            │
                         迎宾主路 ───── OPC 任务广场
                            │             （南侧偏东）
                 五六零人工智能AI小镇
                          主校门
                            │
                         迎宾广场
                           南
```

- 主入口位于南侧正中，作为默认到访方向。
- 原南侧任务广场移到南侧偏东，通过短支路连接迎宾主路，保留公共开放属性。
- 海岸主要分布在东南外围及入口两侧；南侧中央保留连续陆地通道，避免让入镇道路被水景截断。
- 主入口面向来访者，中心广场面向入镇后的活动，两处保留不同的视觉重点。

## 4. 访问与登录流程

已确认允许游客浏览。当前先完成游客进入的视觉原型，登录后关联个人身份的流程留到后续阶段。

```text
打开网站
   ↓
主校门欢迎视角
   ├─ 游客进入 → 切换小镇全景 → 浏览公共场所
   ├─ 登录 → 完成账号验证 → 切换小镇全景
   └─ 已登录 → 显示进入小镇 → 切换小镇全景
```

校门到全景使用简短镜头过渡，提供减少动态效果时的直接切换。不要求用户控制小人走过校门，不引入寻路、碰撞或第一人称漫游。

登录失败时保留登录面板并显示明确错误，允许重试；取消登录返回入口。若允许游客，取消后仍可选择游客进入。未获有效登录结果时，不展示“已登录”状态。

登录后的“进入小镇”只表示完成账号登录，不等于获得所有建筑和内容的访问权限。后续场所权限仍由独立的标签与权限规则控制。

若用户选择必须登录，则入口只保留登录及已登录后的进入操作；未完成登录不能进入小镇，并需要把实际认证纳入首版实施范围。

## 5. 界面建议

### 桌面入口

- 校门为主要视觉，门楣名称完整可见，后方露出小镇。
- 页面下部居中放置轻量欢迎面板，避免遮住门楣。
- 面板标题：欢迎来到五六零人工智能AI小镇。
- 简短说明：学习 AI、创作作品、连接伙伴。
- 未登录时显示“登录”和“游客进入”（若批准游客模式）。
- 已登录时显示“进入小镇”，可带已有昵称。

### 手机入口

- 使用适合竖屏的校门构图，完整名称同步放在清晰的网页文字区域。
- 欢迎面板位于底部，按钮足够大；不依赖横向拖动才能找到入口。
- 登录表单采用网页面板承载，键盘弹出时允许滚动，确保输入和提交区域可见。

### 入镇后

- 镜头回到约 45 度俯视，恢复建筑选择和介绍卡片。
- 建议保留一个轻量的“主入口”操作，方便回到校门；游客可由此发起登录。
- 校门是可见的空间实体，点击后显示入口欢迎界面，避免与普通建筑介绍卡片混淆。
- 首版固定居民仍为场景示意人物，不因显示该人物就宣称用户拥有真实账户或完成身份认证。

## 6. 登录实施边界

当前文档保留登录入口的最终流程规划，用户已明确真实登录后置；本次视觉原型不实现真实登录，也尚未选定真实登录方式。

需要先确定是否已有五六零用户系统可供对接。如有，优先评估复用；如没有，再单独比较微信扫码、手机号验证码或其他账号方式，并由用户确认后开发。

注册、找回账号和退出登录等行为随选定的认证方案确定；如现有系统承载这些流程，小镇引导至对应流程，不自行重复搭建。第三方服务、数据库、账号验证与会话管理不能仅靠入口外观实现，需要单独纳入实施清单。

可选实施节奏：

1. 先开发入口外观与游客入镇流程，登录位置标注“登录暂未开放”，不显示可提交的假登录表单；真实登录另批确认后接入。
2. 将入口外观与真实登录一起纳入首版，先明确账号系统与登录方式，再分别提交开发清单。

如果选择必须登录才能进入，则不能采用只有入口外观的方案作为完整首版交付。

## 7. 后续批次调整建议

- 基础底盘批次：预留校门、迎宾广场和南北主路的位置，调整任务广场与海岸布局。
- 建筑外观批次：增加主校门组件和完整名称，形成一个主入口与六个核心场所。
- 交互批次：增加首次入口视角、进入小镇、返回主入口及桌面与手机欢迎面板。
- 认证批次：由用户确认实施时机和登录方案后，单独列清单实施。
- 验收：检查首次到访是否先看到校门、名称是否准确、进入与返回是否顺畅、游客与真实登录状态是否区分，以及手机端入口和表单是否可用。

## 8. 原首批开发提案（已由场地先行批次替代）

建议首批交付一个可在本地浏览器查看的视觉原型，包含：

1. 初始化基础项目与全屏 3D 页面，采用原需求文档建议的技术方向。
2. 搭建底座、迎宾主路、道路分区、海岸和少量绿化。
3. 创建“五六零人工智能AI小镇”校门，以及六个核心场所的初版几何外观和中文名称。
4. 加入中心地标和一个静态的示意居民，供判断比例与风格。
5. 提供校门欢迎视角、“游客进入”后的小镇全景，以及受限旋转和缩放，支持电脑与手机基础浏览。
6. 完成本地运行、构建和基础布局检查，交付可查看的雏形与当前限制说明。

该批验收重点：校门名称准确、主入口醒目、六个场所可辨识、道路关系清楚、蓝白滨海风格统一、全景取景合理。

建筑点击卡片、复杂高亮、细节动画和实际业务功能后续单独列批次。该清单尚未获开发确认，不自动授权初始化、编码、接入服务或部署。
