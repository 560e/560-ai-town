# 五六零AI小镇管理后台完整规划 V1

日期：2026-09-19。状态：方案待确认，未实施本文件中的新增功能。

后续设计更新：用户已确认按用户中心、运营管理中心、超级管理员后台进行设计。页面结构与权限分层以 [三中心设计方案_V1](三中心设计方案_V1.md) 为准；本文件保留七区业务规划供参考。

## 目标与当前基础

将现有“居民管理”单页扩展为统一的小镇运营后台。管理范围覆盖用户、七个街区、内容、权限与系统设置；具体业务按批次交付，每批先列范围，由用户确认。

已有基础：本地手机号注册登录、居民资料、管理员用户列表/搜索/详情、停用恢复及账户操作记录。账户数据保存在 PostgreSQL，真实短信和正式部署尚未开放。

## 页面结构

- 左侧分组菜单：工作台、用户与组织、七区运营、内容运营、系统管理。顶部显示当前模块、管理员身份和返回小镇入口。
- 工作区统一使用面包屑、标题说明、查询筛选、列表、分页及新建/编辑页面。手机端侧栏收为抽屉，宽表格只在表格容器内滚动。
- 保持小镇蓝白配色，浅色背景和清晰文字。后台侧重信息阅读和操作，不在每个管理页面加载 3D 场景。
- 已实现模块显示真实数据；没有数据时显示空状态。尚未实施的业务标记为“待建设”并说明范围，不展示假的统计、记录或可保存按钮。

“七区运营”与“内容运营”避免重复存储：内容作为唯一记录，以所属街区和展示位置关联。七区页面可查看和编辑所属内容，共用发布流程。

## 权限模型

1. 业务身份和后台管理权限分开。一人可同时为居民、学员和 OPC 成员；获得业务认证不会自动成为管理员。
2. 后台角色按模块和动作授权，如查看、编辑、发布、审批、管理用户。建议预设超级管理员、运营管理员、教学管理员、审核员；可按运营实际需要调整。
3. 课程、班级、组织、项目分别有资源级授权。获得学员身份不表示可以访问全部课程；学校合作方不应看到其他学校的学员资料。
4. 每个接口校验角色、动作与资源范围，菜单可见性仅用于改善体验。停用、授权变化、发布和审批留下操作记录。
5. 首批管理员角色变更不能导致最后一位超级管理员失去权限，不能通过修改个人资料或认证申请提升后台权限。

## 数据与发布约定

- 沿用现有七个稳定街区 ID，不改变场景身份，也不自动新增建筑。后台业务配置与 3D 几何外观继续分离。
- 内容至少包含标题、正文/简介、所属街区、状态、更新时间和操作者；适合展示的内容支持排序。
- 对外内容使用草稿、发布、下架状态。首次发布前允许预览；编辑草稿不直接覆盖线上展示，发布才更新前台。
- 首批内容采用受限纯文本和受控字段，暂不开放任意 HTML、脚本、远程模型和文件上传。
- 已被业务引用的数据优先停用或归档，避免直接删除破坏关联；重要操作记录操作者、对象及必要的前后差异，不记录验证码和密钥。
- NPC话语按街区维护，随机抽取已发布的话语；管理员可以编辑和停用，列表为空时使用现有本地默认话语。
- 后台发布内容先应用于已有欢迎页面、NPC对话，以及本批明确新增的公告/介绍入口。尚未建立的课堂、店铺等子页面不能宣称已经联动。

## 推荐实施顺序

### 第一批：后台框架与全镇基础运营（本次建议确认的范围）

1. 将 `/admin` 改为完整后台布局，建立分组菜单、首页工作台和可单独访问的模块页面。
2. 保留并迁移现有居民管理，建立后台角色及模块操作权限，完善统一审计查询；不新增学校隔离或课程授权业务。
3. 建立七区基础配置：介绍、面向对象、开放说明、联系指引等内容的编辑、草稿、预览、发布与下架；场所 ID、几何布局、招牌模型不由内容后台直接修改。
4. 实现欢迎页/公司介绍、公共公告、分街区 NPC 话语管理；接通已有页面、NPC 与轻量公告/街区介绍入口。
5. 后台未开发的业务栏目保留明确的建设说明；不生成假班级、假申请或假统计。
6. 完成数据库迁移、权限与发布流程检查、桌面/手机布局验证、原有小镇回归测试及操作说明。

验收：管理员保存的数据在重启后仍存在；只有发布内容会出现在相应前台；不同后台角色只能执行授权操作；七区都有清楚的管理入口和基础内容；现有游客和居民流程正常。

### 第二批：服务中心申请与认证闭环

居民选择认证类型 → 查看条件并填写申请 → 提交 → 后台查看/退回补充/通过/拒绝 → 居民收到站内结果 → 按审批结果授予业务身份。需同时完成用户提交页面和后台审批，不能只有后台空列表。

具体认证类型、申请字段、材料与授权规则在本批开始前确认；首期优先学员和 OPC，学校合作申请是否独立流程需结合运营方式决定。

### 第三批：学院与任务广场

学院课程/班级/课堂管理及用户授权访问；任务/活动发布与用户报名、提交和审核。先确认教学材料形态、课堂形式、任务完成条件及是否需要老师权限。

### 第四批：创业园、商业街和社区业务

团队与项目、店铺与作品、社区内容和审核；根据用户确认逐项上线。交易、资金结算、住宅分配、多人在线不由本规划自动授权。

### 第五批：正式接入与部署

真实短信、域名与 HTTPS、生产账户启用、备份恢复、部署与运维检查。继续遵守目前“先本地验证，后补短信”的安排。
