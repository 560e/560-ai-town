# 房间选择、密码与房主管理交付说明

日期：2026-09-19。适用于本地已登录居民的主地图多人场景。

## 用户操作

进入小镇后，在在线状态栏点击“切换房间”。可查看开放房间、人数、密码锁标记，搜索号码并进入，或输入未使用的号码创建房间。房间号为 1～999999 的整数；每房最多 50 个在线账号。公开房间密码留空，密码房需正确输入密码。

创建者就是房主。房主在自己房间的列表行可点击“成员管理”，查看在线昵称及房主标记，踢出其他成员；不能踢自己。还可修改房间密码或关闭房间。房主暂时离开但房间仍有人时，仍保留管理权。1 号房是永久公共房，没有居民房主管理权限。

被踢者收到提示，原房间立即不再显示其角色和气泡，双方私聊结束。客户端随后自动回到 1 号公共房；如果满员，按房间号从小到大顺延，跳过密码房、满员房和刚被移出的房间。遇到最早未使用的号码，自动创建无密码房并进入，该用户成为新房房主。关闭房间后成员也使用这一安置规则。踢出不封禁账号，用户仍可按正常入房条件重新加入。

1 号房永久保留。其他房间最后一名有效在线用户离开后立即释放；异常断网等待最后一份约 8 秒租约失效。房间列表、入房及管理请求会清理过期记录，不保留无人房间 12 小时。释放后密码、原房主权限失效，号码可由其他人重新创建。

切换成功保留服务器认可的位置与朝向，镜头不重置，清空旧房的远端角色、气泡和私聊。密码错误、满员、房间被抢先创建等明确失败，不改变原房间。普通首次登录的 1 号房满员时，可用选择器进入或创建其他房间；强制移出的自动顺延单独处理。

## 技术实现

- 沿用同一 Next 应用和域名端口。`POST /api/town/presence` 处理入房、心跳、离开及房间管理；`GET /api/town/rooms` 返回公开房间列表，`view=members` 仅向对应房主返回成员信息。
- PostgreSQL `town_rooms` 保存房号、独立 UUID 代次、创建者、加盐 scrypt 密码摘要。房号释放重用时生成新代次，旧列表和旧房主不能控制新房间。
- 管理和入房通过数据库事务及咨询锁保护。服务端检查有效登录、页面持有者、房主、目标所在房间及代次、容量，客户端不能自行声明房主。
- 密码不写入 URL、浏览器存储或公开响应；查询列表只含房号、人数、是否有密码、是否本人创建及代次。成员管理不返回手机号、会话或聊天内容。
- 账号每分钟最多 30 次房间操作，失败尝试也计数。手动切房与强制移出重连会更新页面持有者，避免旧请求作用于新房间。
- 50 是在线账号容量；完整人物模型预算仍为 30（含自己及 NPC），按原有距离和交互优先级选择，避免盲目增加图形负担。
- 仅主地图联网；服务大厅和其他子页面不新增多人实例、跨房聊天或好友系统。

## 部署与验证

其他开发环境更新代码后先运行 `npm run db:migrate`，再启动应用。本机已完成迁移；本地验证码与回环访问限制保持不变。

```text
npm test
npm run typecheck
npm run test:rooms
npm run test:multiplayer
npm run test:chat
npm run test:accounts
npm run build
```

房间集成检查覆盖密码及容量、失败切房保持原状态、代次隔离、最后离开释放、创建竞争、50 人心跳、房主权限、跨房踢人拒绝、踢出后的聊天清理。自动顺延检查使用连接专属的临时表，模拟 1 号满员、连续密码房与满员房、空号码自动创建、禁止自动返回来源房和过期连接，不填充或修改真实居民的公共房间。

桌面与手机的房间选择及房主管理需要作为回归入口保留。测试数据使用临时账号，并在结束后清理。这里的并发结果只用于本地功能验证，不代表生产持续容量承诺。

## 关键文件

- `lib/rooms.ts`：房间协议和参数规则。
- `lib/server/rooms.ts`：密码、房主操作、成员列表、释放和顺延。
- `lib/server/multiplayer.ts`：在线租约及房间动作衔接。
- `scripts/multiplayer-schema.ts`：房间及在线状态迁移。
- `components/town/RoomPicker.tsx`：搜索、创建、密码和房主成员管理界面。
- `components/town/useTownPresence.ts`：切房、重连、强制移出提示。
- `tests/rooms.integration.mjs`、`tests/room-routing.integration.mjs`：接口与自动安置检查。

最终验收：62 项单元/场景检查、60 项房间接口检查、6 项顺延检查、34 项联机检查、63 项聊天与词库检查、159 项账户/服务检查通过；TypeScript 和生产构建通过。桌面端实际点击踢出后成员消失，测试客户端收到 410 移出提示并自动回到 1 号房；手机 390×844 的成员列表、房主标记及操作按钮已检查。
