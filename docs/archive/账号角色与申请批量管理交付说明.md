# 账号角色与申请批量管理交付说明

日期：2026-09-19。本次包含已确认的账号角色第一批，以及用户追加的申请管理修复。

## 居民申请管理

- 入口：运营管理中心 → AI服务中心 → 居民申请。
- 超级管理员以及具备相应称号审核权限的工作人员，可以审核自己的正式申请。普通居民不能审核；审核权限和可分配业务权限仍按后台岗位设置验证。
- 按待审核、需补充、已通过、未通过、已撤回筛选，再勾选单条或当前页全部记录；填写原因，统一通过、退回补充、拒绝或删除。当前页20条，接口每批最多50条。
- 每条申请分别检查操作范围、版本、状态和申请条件。已处理、版本过期或无权限的条目跳过，页面列出每条结果。条件变更时依旧退回用户重新确认，不擅自授予新权益。
- 行内“删除”会选中该条并切到删除操作，填写原因后再点击“确认删除”。不会点击一次就删除。
- 删除采用逻辑删除：移出运营和个人申请列表，保留提交内容、时间线及审计记录；原有称号和权限不撤销。删除的待办释放同称号的进行中申请限制，允许重新申请。用户消息会说明删除原因，旧消息不再链接已删除详情。
- 删除记录包含操作者、原因、时间、原状态。没有新增永久清除或前台恢复入口。
- 没有修改任何真实居民申请的处理结果。验证使用临时测试记录并清理。

## 账号角色第一批

- 个人中心提供6种发型、6种发色、8种上衣颜色及可旋转3D预览。保存资料后，小镇和服务大厅中的本人模型读取同一账号配置。图标头像仍可独立设置。
- 本人头顶显示账号昵称和“我”，NPC显示已有名字及NPC标识。本人保留绿色箭头和脚下标记；第一视角隐藏自己的头顶文字，远处名称淡出。
- 昵称2–20字符，全局唯一。规范化全角、首尾空白和连续空格；唯一性忽略英文大小写。数据库约束处理并发争抢，重复时提示“这个昵称已被使用，请换一个”，其他资料不被部分保存。
- 历史账号采用默认外观；旧客户端未提交外观时保留原配置。迁移若发现已有重复昵称会明确停止，不自动改名。
- 角色仍是本地可操控模型。真正多人位置同步、30人实例分流和公共聊天属于计划第二批，尚未实施。

## 关键实现

- `lib/character.ts`：外观预设与输入校验；`scripts/character-schema.ts`：昵称唯一索引和账号外观字段。
- `components/account/CharacterEditor.tsx`、`CharacterPreview.tsx`：个人中心形象编辑。
- `components/town/resident-parts.ts`、`TownPlayer.tsx`、`CharacterName.tsx`：本地几何发型、本人形象与名称显示。
- `lib/server/service-applications.ts`：申请删除、逐条审核、批量事务与结果。
- `components/service/ApplicationManagementTable.tsx`：状态筛选后的勾选与批量处理界面。
- `scripts/service-schema.ts`：删除字段、排除已删除记录的进行中申请唯一索引。

在其他环境更新代码后，先运行 `npm run db:migrate`。本地数据库已完成迁移。仍为本地验证码测试环境，未接入生产短信。
