# V0.0.1 宝塔部署与加载故障修复（2026-09-20）

本地项目是源代码的最终版本。修改先落本地，再同步服务器；服务器密码、私钥、数据库连接串和私人后台入口不进入代码或安装包。

## 本次原因

1. 标准脚本固定部署到 `/opt/560-town/current`，上传目录只是安装来源。宝塔站点目录与 systemd 实际运行目录不同，修改上传目录不生效。
2. 模式1运行 `next dev`，属于开发测试服务。浏览器从 `opc.560e.com` 访问时，Next.js 拦截未放行来源的 `/_next/hmr`。服务器日志确实记录了 `Blocked cross-origin request`。首页 HTTP 200 只证明 HTML 返回成功，不证明前端初始化或3D加载完成。
3. 宝塔原代理把 Host 固定为 127.0.0.1，并对 JS/CSS 设置一分钟缓存。测试服务需要保留实际来源并关闭缓存，避免开发资源版本不一致。
4. SSH 隧道此前未在用户电脑上成功建立，`localhost:56043` 无监听；建立隧道后欢迎页、3D沙盘和账户接口正常。
5. PostgreSQL 18.0 满足要求，先前安装失败是 opc560 账号缺少 public schema CREATE 权限，不是数据库版本或连接密码错误。脚本现在区分这些提示。

## 目录与端口

- 实际代码、依赖、构建目录：`/srv/560-ai-town`
- systemd 服务：`560-town`，用户 town560，监听 `127.0.0.1:56043`，宝塔 Nginx 反代到此端口。
- `/opt/560-town/current` 保留为兼容符号链接，指向上述实际目录。
- `/opt/560-town/shared` 保留数据库连接配置、密钥、上传素材及备份；不移入可能被 Web 服务器直接读取的源码目录。
- Node24 专用运行时保留 `/opt/560-town-runtime`。系统 Node 与其他网站不受影响。

## 已有标准部署迁移到宝塔目录

本工具迁移同版本的现有运行实例，保留数据库、上传素材和密钥，不重新初始化数据库，不用于跨版本业务升级。

把包含本次修复的完整源码包放到服务器（与运行目录分开也可以），在包目录运行：

```bash
bash migrate-baota.sh /srv/560-ai-town opc.560e.com
```

它检查路径、创建候选目录，复制当前运行实例和本批修复，完成类型检查、测试、构建后短暂停服切换。目标目录已有内容会改名为同父目录下的 `.560-town-before-时间`，不删除；配置及原 systemd 备份在 shared/backups。失败会尝试恢复原目录和服务。新安装仍先运行标准 deploy-debian.sh 进行数据库和系统账户配置，再迁移。标准安装器检测已绑定宝塔目录后会停止，避免误切回 /opt 的版本。

宝塔代理模板：`scripts/deploy/baota-proxy.conf.example`。替换当前站点原有的 `location /`，不要重复添加。保留 HTTPS 证书、ACME验证和其他站点配置，先 nginx -t，再重载。仅允许具体预览域名，不使用通配域名放行。

本项目站点可用 `bash scripts/deploy/apply-baota-proxy.sh /www/server/panel/vhost/nginx/proxy/opc.560e.com/已有配置文件.conf` 应用模板；脚本先备份，再检查语法、重载，失败尝试恢复。它只接受本项目现有代理文件，不修改其他网站。

## 访问范围不能混淆

- 公网域名：本批修复支持小镇游客预览，不开放测试验证码。
- 本地 SSH 隧道：测试注册、登录和已授权的用户模块；验证码仍仅向本机开发访问返回。
- 正式公网注册：仍需开发阿里云短信适配及正式认证模式；仅修改 Host、允许来源或 NODE_ENV 不能完成。
- 模式1的页面、JS/CSS、API和HMR不应启用CDN缓存。正式生产构建上线后才对带内容哈希的 `/_next/static` 设置长期缓存；不要缓存账号接口。

## 再次出现加载问题

```bash
systemctl show 560-town -p WorkingDirectory -p ExecStart
systemctl status 560-town --no-pager
journalctl -u 560-town -n 80 --no-pager
curl -I http://127.0.0.1:56043/
```

对照浏览器实际访问地址检查 F12：JS/CSS 是否200、热更新 WebSocket 是否101、是否出现脚本异常，以及欢迎页和3D沙盘是否真实显示。不要仅凭首页200判断成功。

数据库缺表提示若随后完成迁移且应用正常，不要重复盲目运行第三方 auth migrate。数据库检查失败先用同一主机、端口、应用账号检查 server_version 和 has_schema_privilege；管理员连接也应明确 TCP 地址，不能假定默认 Unix Socket 存在。

日常启停继续使用 systemctl 或 manage-debian.sh。不要同时在宝塔创建另一个56043端口的Node进程，否则会端口冲突。源码更新需要候选构建、备份和回滚，不能用旧安装包覆盖当前目录。
