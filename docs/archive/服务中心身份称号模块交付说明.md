# 服务中心身份称号模块交付说明

交付日期：2026-09-19。本次实现用户确认的《服务中心身份称号与权限规划 V2》首批范围，继续使用现有 Next.js、Better Auth 和 PostgreSQL，不新增端口。

## 使用入口

- 用户入口：`/service`，身份展示板、称号详情、申请表及服务向导。
- 个人入口：`/account/applications`，权限称号、荣誉称号、具体资料权益、申请进度和办理通知；个人中心已添加入口。
- 运营入口：现有运营管理中心 → 版块管理 → AI服务中心，包括身份称号、居民申请、授予记录、展示板与资料。
- 超管入口：现有系统管理后台 → 服务中心岗位，配置运营工作人员的操作权限、称号范围和允许分配的业务权益。
- 3D入口：步行导航前往服务中心，在固定向导附近按E或点击提示，对话后打开展示板；沙盘中可点击入口牌进入服务页面。服务页面“返回小镇”回到服务中心门前。普通首页刷新仍显示欢迎页。

## 运营设置顺序

1. 在“展示板与资料”设置服务介绍、NPC欢迎语和办理说明，支持保存草稿、预览和发布。
2. 按需新建服务资料。公开资料游客可阅读；授权资料只有具备有效权限称号的登录居民可阅读。第一批资料为纯文本，不含附件、富文本脚本或外部模型。
3. 新建身份称号，配置名称、荣誉/权限类型、徽章、颜色、所属版块、介绍、条件、有效天数、排序和NPC台词。内部备注独立保存，不进入公共接口和用户申请快照。
4. 配置申请表：短文字、长文字、单选、多选、HTTPS作品链接；支持必填、说明、顺序和选项。每个表单最多12字段，选择字段2–12选项。
5. 权限称号可选择已发布的授权资料阅读权限。荣誉称号无法绑定权限。没有资料时可先建立身份资格，不会虚构学院、班级或项目权限。
6. 分别设置是否公开、是否接受申请，然后发布。公开且接受申请的称号提供申请入口；公开但不接受申请的称号仅介绍获得方式；未公开称号只供后台定向授予。
7. 如需运营人员分工，超管先将账户设置为运营管理员，再在“服务中心岗位”授予维护、发布、审核、定向授予、撤销、内容维护等职责，并限定称号和可分配资料权限。拥有部分称号范围的工作人员不能新建其他称号。

“所属版块”用于展示分类，不代表自动获得整个版块所有业务权限。正式称号名称、申请内容和权益由运营配置，本次测试数据均已清除。

## 申请和审核

支持草稿 → 待审核 → 通过、退回补充或拒绝；申请人可撤回进行中的申请。每名居民对同一称号最多有一条进行中的申请；已持有有效称号时不能重复申请或授予。

审核前填写处理原因。未提交草稿和未提交补充内容只对申请人可见；后台看到最后一次正式提交及历次提交快照。申请条件、表单或权益在提交后发生变化时，批准操作会退回申请，要求居民采用新表单并确认新条件。

申请通过与称号发放在同一数据库事务内完成，重复或并发审批只能成功一次。按2026-09-19用户修正，有对应审核权限的工作人员可以审核自己的申请，仍不能给自己定向授予称号。申请删除与批量处理见《账号角色与申请批量管理交付说明》。结果、授予和撤销写入本人站内通知；通知不发送短信。

## 称号与权限规则

- 账户角色与业务称号独立。称号不会提升运营或超管身份。
- 权限依据服务端的有效授予记录和称号当前已发布绑定计算；到期、撤销和账户停用后立即停止相关访问。
- 多个称号可提供同一权限，撤销一个来源不会影响另一个有效来源。
- 更改现有持有人的权限绑定必须明确确认影响人数，并通知持有人。修改称号有效天数仅影响以后授予，既有记录保留原到期时间。
- 未公开、暂停申请或归档不会自动撤销已有称号；既有申请可继续处理。归档停止新申请和新的定向授予，保留历史记录。
- 草稿和发布使用版本号，过期编辑不能覆盖新版本。身份发布、申请、审批、岗位授权、授予和撤销均写入审计。
- 已发布称号的荣誉/权限类型不能直接互换；已发布资料的公开方式不能直接互换，避免无意扩大可见范围。

## 开发位置

- `lib/service.ts`：称号、动态字段、岗位类型与输入校验。
- `lib/server/service-*.ts`：实时权限、公开目录、申请事务、发布及岗位授权。
- `scripts/service-schema.ts`：可重复执行的数据库结构迁移，由 `npm run db:migrate` 调用。
- `app/api/service/`、`app/api/account/service/`、`app/api/account/applications/`、`app/api/manage/service/`、`app/api/system/service-staff/`：公共、本人、运营、系统接口。
- `components/service/`、`app/service.css`：服务页面、申请表、个人身份、运营编辑器和岗位设置。
- `components/town/ServiceEntrance.tsx`、`data/service-entrance.ts`：本地几何NPC、入口牌和位置；交互与碰撞接入现有小镇逻辑。
- `tests/service.test.ts`、`tests/service-checks.mjs`：字段、入口与服务业务验收；接口检查纳入 `npm run test:accounts`。

本地账户模式启动前执行 `npm run local:setup` 或 `npm run db:migrate`，保持已有环境变量和私有管理路径。已有本地数据库已完成迁移，无需重新建库。

## 当前边界

这是本地开发验收版本。真实短信仍未接入，生产模式账户接口继续关闭；构建通过不代表可直接公开运营。本批未开发课程、班级、学校组织、项目业务、自动评奖、证件附件、大模型客服或多人联机。

首个真实权限资源为服务资料阅读。后续开发学院、任务和项目时，应新增稳定资源ID、动作和服务端鉴权，再加入可分配权限目录。仅添加前端菜单不能视为业务授权完成。
