# 主地图多人在线交付说明

日期：2026-09-19。用户已确认第二批主地图多人在线范围。

## 使用方式

登录后点击“游览小镇”，即可进入在线房间；全景和步行模式共享同一房间。页面显示房间编号和实际在线用户数。游客继续使用本地公共场景，不作为注册居民广播。

不同账号在同一房间中可以看到彼此保存的昵称、发型、发色、服装，以及移动、转向和坐下/起身状态。本人保留绿色标记，其他用户标注“居民”，NPC标注“NPC”。现有“前往”导航依旧到固定门口位置。

同一账号在多个页面打开小镇时只占一个在线位置。新页面提示“此账号正在另一页面游览”，点击“在此页面继续”可以接管；旧页面停止上传自己的状态，旧页面退出也不会把新页面踢走。另一页面失去连接、租约到期后可自动重新连接，不会连续自动抢占一个仍活跃的页面。

进入个人中心、服务大厅或其他子页面，以及回到欢迎页时，当前页面退出主地图在线会话。正常离开及时通知服务器；异常断开后最长约8秒租约到期移除。恢复连接后重新入房，服务器可能修正断线期间的本地位置。账号退出登录、会话到期或被停用后，不再出现在有效在线列表中。

## 人数和画面

- 每个房间最多50个有效在线账号，入房通过数据库事务串行分配。支持选择/创建数字房间、密码房和房主管理；被踢后优先进入1号房，满员时按号码顺延。详见《房间选择密码与房主管理交付说明》。
- 画面最多30个完整人物模型（含本人、其他用户及NPC）。预留本人位置，优先当前交互NPC、附近服务向导、其他用户，再选择附近NPC。
- 名单选择保留距离缓冲，避免距离边界附近频繁切换。隐藏NPC不会留下不可见的对话提示或阻挡玩家。
- “在线人数”只统计账号，不统计NPC；被渲染预算隐藏的用户仍属于在线人数。
- 其他用户位置采用平滑插值，固定导航远距离跳转和坐下位置直接定位，避免穿越整张地图的飞行动画。
- 玩家之间无硬碰撞；本批长凳不做独占预约，可以同步各自坐姿。

## 实现与部署

仍然运行在现有Next应用中，使用同源 `POST /api/town/presence`，没有新增公开端口、独立联机进程或远程模型依赖。当前使用请求/快照同步：前台单个请求完成后间隔250毫秒再次同步，后台页面适当降频。实际更新频率受网络和服务器响应耗时影响。HTTP短轮询适用于本轮本地验证；尚未实施WebSocket推送。

PostgreSQL的 `town_presence` 保存临时在线状态，按账号唯一。记录包括会话、页面持有者、房间、位置、单调递增序号及心跳时间。不同Next进程共享数据库状态，不依赖某个进程的内存。过期记录不参与在线统计，超过一天的残留在入房时清理。

服务端从现有登录会话确定身份，再核验数据库会话有效期及账户状态。客户端不能指定别人的身份、姓名、外观或权限；房间选择由服务端校验密码、容量及房间代次。公开快照只输出角色标识、昵称、外观和姿态，不输出手机号、会话、管理角色及私有入口。

移动检查复用主地图边界、障碍和长凳定义，限制速度和非法穿越。快速导航仅接受已有的目的地枚举。过期序号、无效姿态及过快请求被拒绝；非法位置返回服务器认可的姿态。

更新其他开发环境后执行：

```text
npm run db:migrate
npm run dev
```

本机数据库已完成迁移。现有本地验证码与回环访问限制保留；生产短信和公开网络登录仍是后续独立工作。

## 关键文件

- `lib/multiplayer.ts`：协议、边界/速度校验、分房和渲染名单规则。
- `lib/server/multiplayer.ts`、`app/api/town/presence/route.ts`：会话鉴权、事务入房、心跳和快照。
- `scripts/multiplayer-schema.ts`：在线状态表和索引。
- `components/town/useTownPresence.ts`：客户端连接、重试、接管和退出。
- `components/town/TownOnlineResidents.tsx`：远端角色平滑移动与人物显示预算。
- `TownPlayer.tsx`、`CharacterName.tsx`：复用账号外观与名称，区分本人、居民和NPC。

## 本轮范围边界

只同步主地图用户。NPC与小车仍是各页面的本地模拟；服务大厅多人、跨房交流、好友、长凳预约和管理后台在线调度没有加入。后续已确认并完成同房间公开气泡、靠近邀请且同意后的双方私聊，以及服务器敏感词拦截与运营词库管理，详见《多人聊天与敏感词管理交付说明》。

后续已完成房间选择器、50人房间及房主管理；房主的踢出只改变房间成员关系，不封禁账户。
