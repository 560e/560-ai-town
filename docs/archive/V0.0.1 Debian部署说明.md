# V0.0.1 Debian 部署说明

## 一、先选测试方式

| 模式 | 访问方式 | 能测试什么 | 启动方式 |
| --- | --- | --- | --- |
| 1：完整功能测试，默认推荐 | 每位测试者使用SSH隧道，再打开自己电脑的 localhost | 注册、居民工作台、服务申请、多人、聊天、运营/超管 | `next dev`，只监听127.0.0.1 |
| 2：公网游客预览 | 服务器IP或域名，Nginx提供HTTP入口 | 欢迎页、沙盘、主地图游客互动 | `next build` + `next start`，应用只监听127.0.0.1 |

当前项目未接真实短信，生产环境账户入口被代码主动关闭。模式1是放在服务器上的受控测试环境，不能代表生产性能；模式2没有公网注册、真人多人登录或后台登录。不要把模式1反向代理到公网，也不要修改Host伪造回环来绕过限制。

两种模式均使用同一套应用路径，无需为个人中心、运营中心、超管各开端口。默认内部3000端口；模式1外部只需SSH，模式2外部HTTP80（后续HTTPS443）。数据库不需要向公网开放。

## 二、服务器准备

- 支持目标：Debian 12或13，x86_64/arm64，正常运行systemd的主机或虚拟机；不是无systemd的普通容器。
- 建议测试配置：2核、4GB内存、10GB以上可用磁盘；同时构建或并发测试建议4核8GB。此为准备建议，不是已测并发容量承诺。
- 有sudo/root权限；可以连接Debian软件源、nodejs.org、npm依赖源。
- PostgreSQL15+；可让脚本安装本机数据库，也可填写已有数据库（需应用用户拥有专用数据库及public schema建表/迁移权限）。本机自动安装默认使用5432端口。
- 确保测试电脑需要使用的本地端口空闲，尤其开发机已经运行localhost:3000时，建议部署选择3100。
- 游客预览请选择没有被服务器其他网站使用的独立域名，例如 `test.560e.com`，提前解析到服务器。脚本不覆盖已有默认网站，不自动修改DNS、云安全组、防火墙或申请TLS证书。

脚本使用官方Node.js24 Linux发布包与同源SHA-256校验，安装到 `/opt/560-town-runtime`，不替换服务器其他应用的Node。适用版本参考：[Node.js 24官方发布](https://nodejs.org/dist/latest-v24.x/)、[Debian 13发布说明](https://www.debian.org/releases/trixie/release-notes.en.html)。

## 三、上传、校验和解压

发布文件：`560-ai-town-v0.0.1.tar.gz`，配套 `560-ai-town-v0.0.1.tar.gz.sha256`。在Windows终端上传：

```powershell
scp 560-ai-town-v0.0.1.tar.gz 560-ai-town-v0.0.1.tar.gz.sha256 你的SSH用户@服务器地址:~/
```

登录服务器后：

```bash
cd ~
sha256sum -c 560-ai-town-v0.0.1.tar.gz.sha256
tar -xzf 560-ai-town-v0.0.1.tar.gz
cd 560-ai-town-v0.0.1
sha256sum -c FILES.sha256
sudo bash deploy-debian.sh
```

请在交互终端运行，不要把密码写在命令参数、聊天消息或shell脚本里。不要用 `bash -x` 跟踪部署。脚本会先安装基础依赖，再显示配置向导。

## 四、向导会询问什么

1. 完整测试还是游客预览。
2. 应用内部端口，默认3000。若被占用，会提示输入其他端口并给出下一个端口建议；逐次检查到你选择的端口空闲为止，不会结束整个向导，也不会停止占用端口的服务。
3. 游客预览的域名/IP；完整测试自动使用localhost。
4. 新建本机数据库，还是连接已有数据库。
5. 已有数据库的地址、端口；数据库名、应用用户名。
6. 数据库密码，隐藏输入；新建时要求重复确认。
7. 远程数据库TLS：默认验证证书，可信内网可明确选择不用TLS。
8. 显示不含密码的部署摘要，输入yes执行。

数据库名和用户名限制为小写字母开头、字母数字下划线，最多40字符。数据库密码支持空格、中文、`@`、`#`等符号，会做连接串编码；要求至少12字符。外部数据库目前输入界面支持IPv4/域名，不支持IPv6字面地址。

本机新建模式通过系统postgres用户建立低权限应用角色，不需要填写postgres超级管理员密码。发现同名角色或数据库会停止，不会替换密码或删除已有库；如果这些对象已存在，请重跑向导选择“已有数据库”。若本机PostgreSQL不是5432或不存在正常默认集群，也选择已有数据库模式。

远程数据库如果使用私有CA，需要先让操作系统/Node信任对应CA；本轮不提供忽略证书校验的开关。

随后自动执行：复制源码 → `npm ci` → 数据库验证 → 保存随机密钥/随机管理路径 → 类型检查/回归/构建 → 建表迁移 → systemd启动 → 本机页面和认证模式健康检查 → 可选Nginx代理。

首次启动前还会复查端口；如果安装过程中被其他程序占用，将再次提示选择并同步保存访问地址、认证Origin、systemd端口、Nginx上游及SSH提示。未完成安装的重试也会检查已保存端口。正常升级保留既有小镇服务的端口，不会把它自身的监听当成其他程序冲突。监听检查和真正启动之间仍可能发生极短的竞争，此时由启动健康检查报错，不会抢占端口。

旧的前台 `start-linux.sh` 已有端口占用报错，也可显式执行 `bash start-linux.sh --port 3100`；本次“原地重新输入端口”用于 `deploy-debian.sh` 的交互部署向导。

初次安装不会自动创建超级管理员、指定测试居民或导入开发机数据；因此没有通用默认管理密码或固定5600验证码。

## 五、完整功能测试与第一位超管

例如部署选择3100端口，测试者在自己的Windows PowerShell执行：

```powershell
ssh -N -L 3100:127.0.0.1:3100 你的SSH用户@服务器地址
```

保持窗口打开，再访问 `http://localhost:3100`。本地映射端口应与部署填写的端口一致，才能匹配现有认证Origin配置。若3100被占用，首次部署时换一个双方都空闲的端口。

每个朋友在各自电脑上连接同一服务器、保持同样的隧道目标端口，登录不同账号，再进入相同房间号，就能测试多人。使用各自获授权的SSH账号，不需要共享服务器root密码。仅输入房间号不能绕过SSH访问门槛。

1. 在页面使用真实属于测试者的手机号注册；本轮不会发送短信，表单会显示本地随机测试验证码。
2. 第一位负责人注册完成后，在服务器发布目录执行：

```bash
sudo bash manage-debian.sh admin
```

3. 输入该已注册手机号，授权为超级管理员；命令会撤销该账号现有会话，重新登录个人中心即可看到管理入口。
4. 超管可按需要设置工作人员及服务岗位，再由运营配置分类、称号、公开资料、申请表。

`admin`是服务器维护命令，不是网页路径。随机运营/超管路径存储在私密部署配置中，登录个人中心后会按权限显示入口。

## 六、游客预览与HTTPS

游客模式生成独立的 `/etc/nginx/sites-available/560-town` 和启用链接，不修改其他站点。通过 `http://你的域名` 查看；如无法访问，检查DNS、云安全组、服务器防火墙的80端口及已有Nginx域名冲突。

本脚本不会自动获取证书，也不会默认为80端口网站配置HTTPS。需要HTTPS时，先在DNS正确、80/443可访问的情况下按服务器原有证书管理方式为这个独立站点配置证书；证书文件和续期由服务器管理。仅游客演示也建议在外部分享前配置HTTPS。接入正式登录前必须同时完成生产认证与短信，不能只加证书就认为已经开放账户功能。

## 七、安装目录与配置

```text
/opt/560-town-runtime/                 # 专用Node.js24
/opt/560-town/
  current -> releases/v0.0.1-时间/     # 当前代码版本
  releases/                           # 保留每次部署的代码/依赖/构建
  shared/
    deploy.json                       # root私密向导配置
    .env.local                        # 应用可读的运行配置
    local/site-assets/                # 上传Logo等图片
    backups/                          # 数据库和素材备份
/etc/systemd/system/560-town.service
/etc/nginx/sites-available/560-town     # 仅游客预览
```

应用由专用低权限系统用户 `town560` 运行，默认开机启动。上传目录从每次版本共享，更新不会丢失Logo等资源。数据库保存在PostgreSQL自己的数据目录，独立于源码。

`deploy.json`和`.env.local`含数据库密码、认证密钥和私有路径，不要外发。不要随意手改部署模式：需要同时考虑Origin、systemd、Nginx及认证限制。本轮复用原配置升级，不提供在线切换模式的向导。

## 八、维护命令

在原发布目录或 `/opt/560-town/current` 中执行：

```bash
sudo bash manage-debian.sh status
sudo bash manage-debian.sh logs
sudo bash manage-debian.sh restart
sudo bash manage-debian.sh stop
sudo bash manage-debian.sh start
sudo bash manage-debian.sh backup
```

也可直接使用 `sudo systemctl status 560-town` 或 `sudo journalctl -u 560-town -n 100 --no-pager`。日志没有预置密码，但对外求助前仍应检查是否含个人信息。

手动备份会短暂停止正在运行的应用，完成后恢复原运行状态；保存数据库custom dump、素材与私密配置压缩包。备份同样属于敏感文件，应另行保存到受控位置，不能作为宣传资料分享。

## 九、升级、失败与恢复

把新包解压到新的目录，再执行新目录的 `sudo bash deploy-debian.sh`。发现已有受管理配置后，会询问是否保留配置更新。

- 先安装、检查和构建候选版本，失败不会停止旧服务。
- 更新阶段停止旧服务，备份数据库/上传素材/配置，再迁移、切换代码并启动。
- 新版本启动失败时尝试恢复旧代码服务；数据库迁移不是自动可逆，代码恢复不等于数据恢复。
- 从不自动删除旧库、旧代码或备份。磁盘会随部署次数增长，确认可恢复后再由管理员清理。
- 第一次建库后中途失败且未保存向导配置时，重跑应选择已有数据库，输入刚才的账号密码；数据库不会被重新覆盖。
- `pg_dump`的主版本必须不低于数据库主版本。Debian默认客户端版本不足以备份更高版本远程库时，请管理员先安装匹配客户端，备份失败会中止升级。

数据恢复建议采用“恢复到新库后再切换”，不要直接清空正在用的库：

1. 停止应用并保留出错现场及当前备份。
2. 由数据库管理员创建一个新的空数据库，给专用应用角色赋权；用匹配版本的 `pg_restore --no-owner --no-privileges --dbname=新库名 database.dump` 恢复。通过标准PG环境变量/交互认证指定连接，不把密码放进shell历史。
3. 将 `assets-and-config.tar.gz` 解压到新的临时恢复目录，核对素材、配置与备份版本；不要直接把解压目标指定为系统根目录。
4. 由管理员在私密配置中同时调整 `deploy.json` 的数据库URL与 `.env.local` 的 `DATABASE_URL`，恢复对应素材并检查root/town560权限。
5. 将 `current` 指回匹配的备份代码版本，重启并验收。保留原数据库，确认业务完整后再决定清理。

恢复会改变数据状态，未做一键覆盖按钮。普通停启、备份和更新已由脚本提供。

## 十、首次验收清单

- 欢迎页、全景、步行、360°镜头、七区门口导航、长凳、NPC、环境声、右键拦截正常；游客点击七区入口显示注册提示，直接访问子页和内容接口也不能绕过。
- 在模式1注册两名测试居民，昵称不可重复，修改外观后保存。
- 授权超管后，能通过个人中心进入运营和系统后台；普通居民不能使用管理接口。
- 配置一个公开称号，服务中心可展示、申请、审核，个人中心能看到通知与身份；显示身份最多10个，头顶先显示6个。
- 两台电脑/两个账号进入同房间，互见角色与气泡，私聊需双方同意；房间密码和房主踢人正常。
- 修改站点Logo后重启服务，Logo与数据库内容仍存在；手动备份成功。
- 模式2账户返回未启用，不能获取本地测试验证码。
