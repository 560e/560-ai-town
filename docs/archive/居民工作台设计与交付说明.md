# 居民工作台设计与交付说明

本批次由用户确认，完成个人中心模块化改版、现有个人业务整理和人物身份展示调整。最新补充规则：昵称下方最多显示6个身份，每排3个、最多2排，更多身份点击“＋数量”展开；可选择的身份总上限仍为10个。

## 页面结构

入口仍为 `/account`，默认“个人概览”。桌面使用左侧模块导航、右侧工作区；手机使用可收起的模块菜单。支持查询参数直达模块，切换时更新标题和焦点，回到页面顶部。

| 模块 | 地址参数 | 已实现或预留内容 |
| --- | --- | --- |
| 个人概览 | `section=overview` | 居民名片、真实有效身份数量、待办、审核中申请、最近消息、现有授权资料入口 |
| 我的学习 | `section=learning` | 预留班级、课程与公开课、学习记录、作业和证书；可查看学院介绍 |
| 我的企业与共创 | `section=enterprise` | 预留企业成员身份、企业资料、共创项目、入驻申请；可查看创业园介绍 |
| 我的作品与店铺 | `section=works` | 预留作品、收藏、店铺、商品和服务；可查看商业街介绍 |
| 我的任务与活动 | `section=tasks` | 预留任务参与、活动报名、成果与反馈；分别连接任务广场和AI广场 |
| 我的社区 | `section=community` | 预留社区资料、小组、活动和互动记录；可查看社区介绍 |
| 我的服务 | `section=services` | 申请记录及详情、分页、服务消息及标记已读、真实授权资料 |
| 我的身份 | `section=identities` | 身份展示选择、排序、保存；有效身份、荣誉、权限和历史身份分类 |
| 账户与形象 | `section=settings` | 昵称、人物外观、头像、手机号信息、加入时间、退出登录 |

未来模块明确标注“筹备中”，没有虚拟班级、企业、课程、任务、学习进度或不可用的业务按钮。服务中心现有申请入口继续开放；资料入口根据有效业务权限返回。正式业务接入时，应在同一模块内使用真实授权关系决定用户能访问的功能。

## 身份与组织关系

荣誉、权限称号与班级、企业成员关系分别管理。佩戴称号不产生组织成员资格，组织成员身份也不自动公开。后续可关联显示，但不得用徽章配色或用户自行展示的称号代替业务授权。

运营管理中心与超级管理员后台仍为独立入口，只对服务端返回入口的授权账户显示。工作台模块切换不改变系统角色和业务权限。

## 现有功能迁移与兼容

- 复用原登录、资料保存、身份展示设置、申请审批、消息和资料阅读接口。
- `/api/account/service` 的全量进行中申请增加名称字段，用于概览待办；待办与审核中数量不依赖申请列表的当前页。
- 未读数明确针对最近100条服务消息，不冒充全历史未读总数。
- 在工作台内部切换模块时，保留未保存的个人资料和身份展示编辑内容；离开整个工作台或刷新仍以已保存内容为准。
- 原 `/account/applications` 页面地址重定向至新版“我的服务”；申请详情地址保留。服务大厅内嵌的“我的申请”组件继续工作，不因全页重定向跳出大厅。
- 返回小镇沿用既有状态保存机制，保留进入个人中心前的区域、人物位置、镜头与场景模式。
- 无新增数据库字段、依赖包、业务授权体系或端口。

## 人物身份标签

昵称在上，身份在下。排序前6项以三列、最多两排显示；超过6项在旁边显示“＋N”，点击后查看所有已选择的身份，点击按钮再次收起或按Escape关闭。本人、同房间其他居民、服务大厅本人和个人中心预览共用组件。

保持每次最多选择10个有效身份、服务端验证、运营配色、撤销与到期移除、隐私选择等既有规则。远处人物优先显示昵称：当前桌面38场景单位、手机30场景单位外隐藏身份行，沿用原昵称最远显示范围。NPC保留原有名字和NPC标识。

## 实现入口

- `lib/resident-workbench.ts`：模块目录、分组、规划内容、地址解析。
- `components/account/AccountPage.tsx`：工作台框架、概览、未来模块空状态与登录入口。
- `AccountProfile.tsx`：个人资料及形象设置。
- `WorkbenchRecords.tsx`：个人记录加载、身份分类、服务记录与消息。
- `IdentityDisplayEditor.tsx` / `IdentityBadges.tsx`：身份选择和两排展示。
- `app/resident-workbench.css`：独立工作台响应式样式。
- `components/town/CharacterName.tsx`：现有场景共用名牌及距离显示。
