# 人物身份展示 · 交付说明

本批次为用户确认的身份佩戴与样式功能，沿用现有称号授予、业务权限与场景系统。

## 用户操作

- 个人中心新增“头顶身份展示”，账户侧栏可直接定位该区域。
- 默认显示浅灰色“小镇居民”，用户可隐藏。游客不获得居民称号。
- 已获得且有效的称号会出现在选择列表。运营尚未允许头顶展示的称号可查看，但不可勾选；待审批、撤销、过期和未发布称号不可佩戴。
- 最多选择10个身份，包含默认居民身份；拖动或使用上移、下移按钮排序，单独保存展示设置。
- 最新展示规则：昵称下方默认显示最多六个紧凑标签，每排三个、最多两排；超过六个显示“＋数量”，点击可展开全部，昵称始终保留。颜色不代表系统角色或权限等级。
- 展示覆盖主小镇本人、同房间其他居民、服务大厅本人；NPC继续使用原有NPC名字。服务大厅本轮未增加多人同步。

## 运营操作

运营管理中心 → AI服务中心 → 身份称号 → 编辑配置 → 人物头顶称号样式。

“公开到展示板”与“允许持有人选择在人物头顶展示”为独立开关。未公开但定向授予的称号，只有运营明确允许且用户选择后，才会向其他居民显示名称与外观。旧称号和新建称号均默认关闭头顶展示，避免意外公开内部身份；请按运营需要逐项开启并发布。

提供居民浅灰、铜牌、银牌、金牌、海蓝、翡翠、浅紫、炫彩八种样式预设。运营可调整1–3个背景颜色、文字色、边框色，选择纯色或渐变并预览。默认居民是系统内置的浅灰样式，预设中的“居民浅灰”也可应用到运营创建的其他称号。

原“展示板徽章颜色”继续负责展示板图标，本次新增区域负责人物头顶的称号标签。保存草稿不影响已佩戴的外观，“保存并发布”后才生效。称号列表新增“头顶展示”状态列。

## 数据与权限

- `town_profiles.identity_display`：按序保存授予记录ID，居民身份使用 `resident`；默认 `["resident"]`。
- `identity_display_version`：乐观版本控制，拒绝旧页面覆盖新的排序。
- 已发布 `TitleConfig.overheadAllowed` 与 `overheadStyle` 决定展示资格和颜色；旧JSON无字段时默认不允许展示。
- `/api/account/identity-display` GET 返回本人的有效身份与设置，PATCH 保存；`?view=badges` 只返回可展示的公开标签。
- 服务端每次读取都核验授予归属、有效期、撤销状态和已发布展示开关。归档按原有业务规则保留已授予的身份；要禁止展示，应关闭头顶展示并发布或撤销授予。
- 多人快照按当前房间批量读取已选择的身份，避免逐人查询所有称号。公开数据只含标签ID、名字、样式与到期时间，不携带申请内容、手机号、内部备注或权限绑定。
- 自己的标签在前台可见时约每5秒刷新，保存后立即刷新；其他居民标签随既有多人快照更新。客户端也按到期时间移除标签。
- 选择、隐藏、配色、排序均不改变业务权限。重新授予会产生新记录ID，过期或撤销的旧选择不会自动关联到新授予。
- 颜色只接受六位十六进制值，不能提交任意CSS；展示设置保存使用现有登录、同源校验、事务及审计。

## 开发与迁移

新增字段集成于现有角色迁移，部署前执行 `npm run db:migrate`，本地已执行。无需额外端口、依赖包或远程资产。

共享组件：`IdentityBadges` / `IdentityChip` 用于预览和人物标签；`CharacterName` 统一本人、远程居民和大厅人物展示。`IdentityDisplayEditor` 负责个人设置，`TitleAppearanceEditor` 负责运营配色。
