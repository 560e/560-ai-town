# V0.0.3 发布记录

## 发布信息

- 发布日期：2026-09-24；V0.0.2部署构建失败的完整源码修订包。
- 包名：`560-ai-town-v0.0.3.tar.gz`；生成后的外部SHA256、字节数和文件数写入同目录旁车校验及发布收据。包内使用`RELEASE-MANIFEST.json`和`FILES.sha256`定位源码，不编造Git提交。
- 本地验证完成后打包；服务器仍为用户确认的V0.0.1，本批不连接或部署服务器。

## 变更范围

- 修复候选版本在`next build`前把`.local`链接到项目根外共享上传目录，导致Turbopack将有效运行时素材误判为越界链接并中止构建的问题。
- 类型检查、测试和构建使用与运行时一致但不依赖候选链接的受控环境变量；只有生产构建成功后才挂载`.env.local`和`.local`运行时链接。
- 指定候选目录为Turbopack根。`package-lock.json`涉及共享目录的提示仍可出现，但它是非阻断警告。
- 未改动业务数据库、账户、权限、素材内容或真实短信配置；未删除V0.0.2历史归档。

## 验收证据

2026-09-24 Windows/Node24：候选运行时链接边界回归、136项单元/路径/权限测试以及V0.0.3生产构建（含TypeScript）通过。Windows不以实际Linux符号链接代替Linux实装验证；Debian/Ubuntu的首次安装、保留数据升级和回滚仍需目标环境执行验收。

## 升级与恢复

详见[部署运维手册第6节](../部署运维手册.md#6-升级回滚与诊断)。从受管理V0.0.1或V0.0.2安装升级时，使用新源码项目根中的`deploy-linux.sh --install-root /既有项目根`；旧项目根、数据库、端口、素材、配置和管理入口保持不变。候选构建通过后脚本才短暂停服、备份、迁移、切换与健康检查。失败时保留候选和现有数据，并尝试恢复旧代码；数据库不自动回退。
